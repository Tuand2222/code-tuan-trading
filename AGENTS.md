# Project rules

- Scope: preserve Classic/Legacy and the existing backend. Authored code is in `src/core/`, `src/views/classic/`, `src/views/v6/`; contracts are in `schema/`. `lib/journal-*.js`, `lib/trade-normalizer.js` and `lib/trade-form.js` are compatibility exports, not parallel implementations. Classic's framework entry is `app/classic/page.tsx`.
- V6 ships as `v6/index.html`, one HTML file with Tailwind CDN, Chart.js CDN, Inter and JetBrains Mono. Edit `src/views/v6/shell.html`, `src/views/v6/app.js` and `src/core/journal-runtime.js`; generate with `node scripts/render-v6.mjs`. Verification must reject drift before any build can regenerate it. Do not add application libraries.
- Use `v6/docs/02_BLUEPRINT_HOP_NHAT.md` and `v6/docs/04_PDF_DOI_CHIEU_VA_KIEM_TRA_V9.md`. Keep retained DOM, Vietnamese labels and styles; document required exceptions.
- One trade ledger, one cashflow ledger, one RiskMath shared with the generated Worker, one RiskStore. No duplicate IDs, named functions, override wrappers or copied math engines.
- Add a numerical regression test before changing a financial formula. Never fabricate missing risk, fees, statistics or historical data. Keep migrations/restores non-destructive and preserve legacy keys.
- Only explicitly verified Net P&L / 1R feed risk statistics. Preserve `origin`, `CLEAN_SLATE_LOCKED`, the no-mock lock, storage keys and schema. Each write must signal both views. No destructive action without an actually downloaded, checked JSON backup. Fixtures must be synthetic and isolated from production.
- Run `npm run verify`, `npm run build`, and `npm run e2e` in `v6` before pushing a PR. Run root validation when backend/build integration changes. Record actual results and limits in the report.
- Use a feature branch and PR. Follow CONTRIBUTING.md: no direct main commits, force-pushes or merge without human approval. Never commit credentials or real journals. Preserve Site identity and audience when deploying an authorized update.
- CI entry: `npm run ci:check` (source drift, root suites/build, V6 core, mutation guards, all V6 browser suites, actual compiled Classic/V6 sync and Classic lifecycle). Required PR check: `Journal required checks`. CODEOWNERS takes effect only with server-side branch protection requiring code-owner review; do not claim enforcement from this file alone. Record remote CI and protection evidence separately from local results.
